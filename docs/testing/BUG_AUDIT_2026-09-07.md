## Task packet

Player outcome: reloading preserves the order and effects of player actions; repeated
recovery retains a usable backup; invalid save versions cannot masquerade as supported
saves; declaring insolvency stops traffic during that same tick.

Scope: Persistence, the insolvency boundary in AirportSimulation, regression tests,
and the supplementary repository mirror in scripts/dotnet-harness.

Acceptance: reproduce the defects before fixes, pass the complete Unity EditMode suite
afterwards, compile a macOS player, and merge the reviewed bug-fix PR into main.
Save fields and schema 1-to-2 compatibility, art, camera, progression and balancing stay
unchanged. No new product design or visual asset approval is implied by this audit.

## Findings and fixes

| Severity | Defect and reproduction | Fix |
| --- | --- | --- |
| High | Release two crew then hire six at second zero. Live crew = 8; reload crew = 6 because alphabetical command sorting moves hires before releases. Cash also differs. | Stable timestamp ordering preserves the persisted list order within each second, including older IDs. |
| Medium | Two successful hires in the same second before saving both receive `hire-1-0`. | All command entry points use the shared recorder and assign independent persistent GUID identities. IDs do not influence simulation randomness or order. Existing duplicate legacy IDs remain replayable. |
| High | Corrupt primary, recover backup, save, corrupt primary again: both copies become unreadable and load starts a fresh airport. | Validate the actual primary before rotating it; preserve the good backup when replacing invalid data. Mirror the behavior in the headless repository. |
| High | A primary save with schema 0 or -1 is migrated to 2 and accepted instead of falling back to the valid backup. | Reject unsupported versions before migration. Schema 1 still migrates; future versions remain rejected. |
| Medium | A landing due at the third negative midnight proceeds after the Insolvent event. | Recheck insolvency immediately after day settlement, before any aircraft advancement. |
