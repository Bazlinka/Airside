## Task packet

Player outcome: a stable, readable Airside session in which aircraft never conflict on the
ground or runway, player decisions/saves remain trustworthy, the interface stays usable, and
the packaged macOS app is responsive through normal and busy airport operation.

Scope: Domain, Simulation, Persistence, Presentation, controls/audio, runtime art loading,
packaged macOS behaviour, and measured performance. Current unmerged features are audited only
when they are already present in the branch under test; this audit does not add new content,
economy systems, external feeds, or art assets.

Invariants: injected time and seeded randomness; reserved runway/taxiway/stand use; frame-rate
independent outcomes; idempotent commands; save compatibility; and simulation authority over
presentation are preserved.

Acceptance: every confirmed fault has a minimal regression test or documented visual repro;
the full Unity EditMode suite passes; a clean, stamped macOS player builds; packaged-player
smoke/soak checks complete; and performance changes have before/after measurements from the
same scenario. A build is not release-ready merely because it packages.

## Evidence protocol

For every finding, record the exact commit, deterministic seed/time/command sequence or player
steps, expected versus actual behaviour, affected files, test name, and before/after outcome.
Performance entries also record hardware, resolution, quality settings and capture duration.
Do not re-label a changed behaviour as a test update without recording why that behaviour is
intended.
