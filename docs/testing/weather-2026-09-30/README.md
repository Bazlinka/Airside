## Repeatable player review

Build with `scripts/build-mac.sh`, then run `scripts/review-weather.sh`. Captures and Player logs
are kept under ignored `work/captures/weather-final`. The script uses absolute output paths,
1600 × 900 graphics-on players, an untouched player save, noon weather overrides, the existing
soak career, and a 25-second capture delay. Overrides only affect presentation. It also checks
clouds at 20-degree pitch, noon fog while following VH-PAX, and fog at 23:30.

## Rendered acceptance

All six weather kinds were captured and inspected. Added low-angle cloudy and overcast views,
noon fog following VH-PAX, night fog, and 60-second fog/storm warm runs. No shader error,
exception or soak-stall match in the retained player logs. The foreground Saab stays clear while
fog fades the distant terminal; rain streaks are visible at the overview; cloud bodies retain
billowing silhouettes from below and overhead. Night keeps the airfield light points and HUD.

The first fog-box implementation was enabled at full strength in the player but scarcely showed.
The corrected camera proxy reconstructs each pixel's world ray from opaque scene depth and
integrates the 120 m height interval. This was verified in the actual close player capture.
The final shader-only optimization replaced twelve height steps with an analytic exponential
integral and three drifting variation samples; it was recompiled in the Mac player and captured
again. Full Unity tests cover the final C# and four shader-presence/build-inclusion cases.

## Performance scope

All samples: 1600 × 900, graphics on, ordinary world/aircraft visible, vsync 2 and focus true.
Values below are the final ten-second heartbeat from each run, not whole-session averages.
Warm runs use a 60-second capture delay. Short captures use 25 seconds; the comparison uses 40.
The controls do not modify saved graphics choices. They are not simultaneous controlled trials.

Early short views recovered to 59–60 fps. The later warm storm run ended at 37 fps and the
weather-layers-off control at 40 fps. Concurrent read-only process inspection found Chrome's
renderer at 55% CPU and WindowServer at 45%. Weather layers still have a cost; changing clocks,
scene state and background load mean this comparison cannot isolate that cost or establish a
locked 60 fps. No unrelated applications were stopped. A dedicated performance run with stable
background load remains a separate benchmark, not a claim made by this visual pass.
